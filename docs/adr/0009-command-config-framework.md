# ADR-0009：命令框架策略——各平台用各自原生命令框架，命令入口在 L3、执行逻辑抽到共享

## 状态
已接受

## 背景
本脚手架不自建命令框架，也**不为一条管理命令引入重型框架**。评审指出：TabooLib 是一整套带 bootstrap / 独立类加载 / repackage 的框架，仅为命令注册引入偏重，且其 Sponge / 1.12.2 成熟度存疑、与 Brigadier 两套命令模型难统一。故各平台直接用其**原生命令框架**。（配置与资源路径见 [ADR-0010](0010-config-and-resource-paths.md)，与命令解耦。）

## 决策
1. **命令入口（注册 + 参数解析 + 线程切换）在 L3 平台胶水，各平台用原生命令框架**：Bukkit/Spigot/Paper/Folia 用 Bukkit/Paper 原生命令；Sponge 用 Sponge 原生命令；Fabric/Forge/NeoForge 用各自 **Brigadier**。CatServer 以 Bukkit 入口加载（ADR-0008）→ 走 Bukkit 原生命令。
2. **命令与监听器的执行逻辑抽到共享 L0/L1**（平台无关、可单测）；L3 只把解析后的参数转交共享执行层，**不在 L3 写执行逻辑**。
3. **L2 薄命令接缝 `CommandRegistrar`**：只承诺"声明命令名 + 绑定共享执行逻辑"；参数解析 / 补全 / 权限 / 子命令树等用各平台原生能力、**不进接缝**（接缝是最小公约：注册 + 转发到共享执行）。
4. **不引入 TabooLib 或任何重型命令框架**（契合 PRD 非目标"不默认引入重型框架 / 简单优先"）。

## 理由
- 本脚手架命令很少（如 `/mpmt machinecode ban|unban|list`），不值得背 TabooLib 全家桶。
- 各平台用原生框架最轻、最可控，且能用各平台原生的参数树 / 补全 / 权限。
- 执行逻辑共享 → 跨平台一致、可纯 JVM 单测（契合 ADR-0001）。

## 后果
- 正面：零重型命令依赖；各平台命令注册自然；执行逻辑统一、可测。
- 负面：命令注册代码各平台不同（但执行一致）；薄接缝只覆盖"注册 + 转发"。
- 约束（写入 architecture-invariants）：L3 命令注册**不得承载执行逻辑**；命令 / 监听器多在主线程触发、触碰共享可变状态须线程安全，且碰世界 / 实体状态须经**归属调度**（见 [ADR-0013](0013-threading-and-scheduling.md)）。

## 备选方案
- **用 TabooLib 统一服务端软件命令**：重型框架、Sponge/1.12.2 成熟度存疑、与 Brigadier 不同构——否决（评审结论）。
- **自建跨平台命令框架**：重复造轮子——否决。
- **执行逻辑写在各 L3**：散落、不可统一测——否决。
