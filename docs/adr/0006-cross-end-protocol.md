# ADR-0006：跨端通信用自定义协议 + 版本协商，经 TransportPort 适配

## 状态
已接受

## 背景
要支持"任意服务端平台 + 任意客户端平台"自由组合（如 Paper 服务端 + Fabric 客户端），双方不可能共享平台 API，只能靠一份双方都认的通信契约。各平台的底层网络通道（插件消息通道 / 自定义包 / 网络 API）又各不相同。AllinCore 用 `buildSrc/ProtocolManifest` 做协议单一真源 + 协议版本号协商，验证了这条路。

## 决策
- 在 L1 `protocol` 模块定义**跨端协议的单一真源**：包定义、字节布局、方向（S2C/C2S）、协议版本号（`CURRENT` / `MIN_SUPPORTED`）。客户端与服务端共用同一份定义。
- 握手阶段做**版本协商**：依据 `MIN_SUPPORTED` 判断兼容，不兼容则明确拒绝并提示，而非静默错乱。
- 底层收发抽象为 L0 端口 **`TransportPort`**，由各平台 L3 适配到其原生网络通道；`protocol` 不绑定任何具体网络栈。
- **互通前提（评审）**：自定义协议是"双方注册同一通道"才生效的点对点机制——互通要求**服务端与客户端均部署基于本脚手架的对应产物并注册同一 protocol 通道**。服务端经"进服后 N 秒未收到 ClientHello → 判为非本协议端、走原版兼容路径"做**能力探测 / 超时降级**，而非卡死。原版 / 未装我方组件的客户端按非本协议处理。
- **拒绝时机不对称（评审）**：握手是**应用层**握手；Bukkit 插件消息仅在玩家进服（PLAY 阶段）后可用，故 Bukkit 家族只能"**进服后尽快踢出**"，无法进服前拒绝；Fabric/Forge 的 login 阶段拒绝仅作可选增强。详见 network spec。

## 理由
- 单一真源避免客户端 / 服务端协议定义漂移（双源打架是跨端故障高发区）。
- 版本协商保障跨版本 / 跨平台组合下的稳定降级与失败快。
- `TransportPort` 抽象让协议逻辑平台无关、可单测。

## 后果
- 正面：**双端均装我方组件下**任意端组合可互通（桥接价值 = 协议字节与平台 API 解耦，**不等于无需对端配合**）；协议演进可控、可向后兼容。
- 负面：协议是强契约，破坏性变更须经 ADR + CHANGELOG 写明迁移，并维护 `MIN_SUPPORTED`。
- 约束：协议字段 / 布局变更只在 `protocol` 一处改；序列化不得依赖平台类型。

## 备选方案
- **直接复用某平台的高层网络 API**：无法跨平台共用——否决。
- **客户端 / 服务端各自定义协议**：必然漂移——否决（违反单一真源）。
- **无版本协商**：跨版本组合下易静默错乱、难排障——否决。
