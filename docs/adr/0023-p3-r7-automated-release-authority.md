# ADR-0023：P3 R7 严格自动化验收作为 FR-16 的最终发布权威

## 状态

已接受

## 背景

ADR-0014 确立了 realserver 的服务端驱动、客户端验证与单一权威报告。P3 / FR-16 已在真实 Paper、Fabric、Forge 26.2 专用服和程序化客户端进程中，以同一轮 R7 执行 `product-handshake`、`product-roundtrip`、`client-hud` 三个场景；报告同时记录运行标识、开始毫秒、五个制品角色的 SHA-256 与最终结果。

此前 P3 规格额外要求人工实机最终确认，因而即使三车道 R7 严格门通过，FR-16 仍无法作为发布输入。维护者已决定以可复核的真实进程自动化证据作为该期 FR-16 的最终验收权威。

## 决策

1. 仅对 P3 / FR-16，满足以下条件的 `:runP3R7Gate` 通过即为最终自动化验收，无需额外人工实机确认：Paper、Fabric、Forge 三车道为同一 `RUN_ID` 与开始毫秒；Paper 运行时固定为 build 71；每份 `SERVER-GAMETEST-REPORT v2` 的五个制品哈希与当前制品一致；三个 required 场景各恰好一次 PASS，且最终为 `RESULT PASS`。
2. 历史报告、普通构建成功、P2 R1–R6、单元测试或缺少任一车道的报告均不构成该验收证据。
3. 本决定仅细化 ADR-0014 在 P3 / FR-16 的发布权威，不追溯改变 P1、P2 的人工确认记录，也不自动扩张到未来平台或版本扩展；其他范围仍按既有实机确认规则执行。
4. 自动化验收完成不等同发布：FR-17、FR-18 与 `sdd-release-version` 的版本、tag、GitHub Release 规则仍须分别满足。

## 理由

- R7 已运行真实服务端、真实网络连接和客户端验证器，覆盖该期冻结的公共产品场景，并由根门严格核验报告结构、运行轮次和制品来源。
- 将放行条件完整编码为可复核门，避免人工观察与结构化测试结论相互矛盾。
- 以 FR-16 为限，既不降低历史发布证据，也不将该例外误用到尚未设计同等严格门的未来范围。

## 后果

- 正面：当前候选提交的 `p3-r7-1787686232087` 可作为 FR-16 的最终自动化证据，P3 不再被额外人工确认阻断。
- 负面：R7 只覆盖冻结的三个场景，主观视觉体验和范围外玩法仍不因此宣称已验收；任何实测反例仍按缺陷流程修复并重新取得当前报告。
- 约束：报告生成与聚合仍只能经 Gradle 任务；若受控运行时、制品或场景变化，必须重新运行三车道并通过严格门。

## 备选方案

- 保留人工实机最终确认：提供额外主观观察，但与已具备双端断言和哈希约束的 R7 自动化门重复，已否决。
- 以普通 `BUILD SUCCESSFUL` 或单车道报告放行：不能证明真实网络、全矩阵和制品一致性，否决。
