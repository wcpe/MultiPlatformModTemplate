# ADR-0015：功能域组织与拆分约定——域模板 + 注册 + 包→模块成长，不预建空壳

## 状态
已接受

## 背景
随玩法增多，L0 会有多个**功能域**。需一套**组织与成长约定**，让每加一个域都一致、解耦、可单测，又**不预建空壳**（scope-discipline §3）、不上 AllinCore-New 那种大产品式的 per-domain `api`/`impl`/聚合门面重结构（脚手架 YAGNI）。域间**解耦机制**已由 [ADR-0011](0011-eventbus-domain-decoupling.md)（EventBus、互不依赖、全图无环）定；本 ADR 定**域的内部组织、注册、成长规则**。

## 决策
1. **域模板**：每个功能域是自包含单元，初期为 `top.wcpe.mc.mpmt.domain.<name>` 下的**包**（在 L0 `core-domain` 内），含：领域模型 + 领域逻辑/状态机 + 该域**发布/订阅的事件类型** + 该域用到的端口调用。纯 Java 8、可纯 JVM 单测。
2. **依赖规则**：域只依赖 **L0 内核（基类型 / 端口 / EventBus）**，**不依赖兄弟域、不成环**（ADR-0011）；跨域协作只经 EventBus 发布 / 订阅。
3. **注册**：`core-runtime` 启动期经域 / 特性注册表发现并装配各域（FR-02）；域声明其事件订阅 + 启停钩子；**公共层不硬编码具体域列表**（新增域 = 注册一条，不改编排核心）。
4. **成长规则（包 → 模块）**：域**先作 `core-domain` 内的包**；当某域足够大 / 需独立复用 / 需独立版本演进时，**再提升为独立 Gradle 模块**（仍只依赖内核 + EventBus、不依赖兄弟域）。**不预建空域模块 / 空 api-impl 骨架**。
5. **平台相关下沉**：域的 L0 逻辑平台无关；若某域需渲染 / 平台事件，其平台适配在 L3 经端口 / 事件桥接，**不在域内写平台代码**。

## 理由
- 约定先行让 N 个域一致、解耦、可测、可独立成长；包优先 + 按需提升避免预建空壳与过度模块化，契合 YAGNI 与脚手架定位。
- 与 AllinCore-New（大产品、per-domain 模块 + 聚合门面）的差异是**刻意的**：脚手架不交付多领域产品，无需那层重结构。

## 后果
- 正面：加域成本低且一致；域可独立单测 / 拆分；编排核心不随域增长而改。
- 负面：包升模块时需一次小重构（但有明确触发条件）；需自律守"域不互依"——由 ADR-0011 红线 + 构建期依赖校验守护。

## 备选方案
- **重 per-domain 模块结构**（AllinCore-New 式，api/impl/聚合，前期重）——否决（脚手架不需要）。
- **不定约定**（域增长易乱、易互依、难测）——否决（用户要求提前规划好）。
