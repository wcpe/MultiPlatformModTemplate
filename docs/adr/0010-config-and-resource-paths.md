# ADR-0010：配置与资源路径——平台无关共享模块（YAML/JSON 加载工具 + 预设目录/资源位置）

## 状态
已接受

## 背景
配置加载与"目录 / 资源位置"本就**平台无关**，且**客户端与服务端应共享**，否则各平台各写一套配置加载、各处自算路径，易漂移、易错。命令框架因需平台原生支持而走 [ADR-0009](0009-command-config-framework.md)；配置 / 路径与之**解耦**，不经 TabooLib。

## 决策
1. **配置加载 = 平台无关共享工具模块 `core-config`（L1）**：支持 **YAML + JSON**（等）配置文件加载为类型化模型。纯 Java 8。依赖 `snakeyaml`（YAML）+ 轻量 JSON 库（如 `gson`，Java 8 兼容）。**不经 TabooLib**。
2. **目录与资源路径 = 客户端/服务端共享模块 `core-paths`（L1）+ 端口 `DataDirectoryPort`（L0）**：平台经端口提供**基目录**（Bukkit 插件数据目录 / Fabric 配置目录等），共享模块**预设标准位置**（如 `config/`、`data/`、共享 `resources/` / `assets/`）；调用方引用预设（如 `paths.configFile("x.yml")`）**不自算路径**。
3. **客户端与服务端共用同一份路径预设与配置模型**，确保两端一致。

## 理由
- 配置 / 路径平台无关，抽到共享模块一处维护、全平台与单人一致。
- 预设位置避免散落的路径拼接错误；调用方零路径计算。
- 与命令框架解耦（命令需平台原生框架，配置不需要）。

## 后果
- 正面：一处加载、全平台一致、调用方零路径计算；客户端 / 服务端资源位置统一。
- 负面：引入 `snakeyaml` + 轻量 JSON 库依赖（Java 8 兼容，按需最小化）。
- 约束（写入 architecture-invariants）：基目录只经 `DataDirectoryPort` 由平台提供，**共享层不得硬编码绝对路径**；敏感配置不入库、走环境变量（见 SECURITY / `config-files` 规则）；YAML 字段按 `config-files` 规则 kebab-case + 中文注释。

## 备选方案
- **配置交由 TabooLib**：仅覆盖服务端软件、mod 加载器没有，且配置本可平台无关——否决。
- **各平台各写配置加载 / 各处自算路径**：重复、易漂移、易错——否决。
