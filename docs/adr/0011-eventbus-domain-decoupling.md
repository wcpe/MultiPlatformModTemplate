# ADR-0011：功能域事件驱动解耦——自有 EventBus 作域间转发，域间禁止直接 / 循环依赖

## 状态
已接受

## 背景
随玩法增多，L0 将拆成多个**功能域**（如网络 / 封禁 / 会话 / 未来各玩法域）。若域间直接互调，会产生相互 / 循环依赖、紧耦合、难测、难独立拆分。需要一种域间通信机制使各域解耦、可独立增删。全局反模式已禁循环依赖；本项目进一步**禁止任何模块 / 域相互依赖**。

## 决策
1. **自有 EventBus（L0 共享内核，平台无关）**：发布 / 订阅 + **域间事件转发**；各功能域只 `publish` / `subscribe` 事件，**不直接调用其他域**。EventBus 与领域基类型、端口同属 L0 内核，被所有域依赖（向内依赖，合规）。其订阅 / 发布接口即 `EventBusPort`，**自有 EventBus 是该接口的 L0 内核默认实现**——"接口 + 内核实现"是一套机制、非两套；它不是平台端口（无 L3 平台实现）。
2. **平台事件桥接进 EventBus**：平台原生事件（Bukkit `PlayerJoinEvent` / Fabric 事件等）经各 L3 适配器转成领域事件投递到同一 EventBus；网络包到达后亦可转成事件分发（先经 `SchedulerPort` 切线程）。
3. **功能域之间禁止直接依赖**：域只依赖共享内核（领域基类型 / 端口 / EventBus），**不依赖兄弟域**；跨域协作一律经事件转发。
4. **禁止任何模块 / 域相互依赖与循环依赖**：把分层"依赖只向内"强化为"**全依赖图无环、同层域之间无互依**"。

## 理由
- 事件驱动让域松耦合、可独立拆分 / 增删；新增玩法域 = 订阅 / 发布事件，不动他域。
- 自有 EventBus 平台无关、可纯 JVM 单测、跨端一致（不复用平台事件系统）。
- 无环依赖保证可构建、可测、可演进。

## 后果
- 正面：域可独立演进 / 拆分；可对单域注入假事件单测；跨端事件一致。
- 负面：事件流可追踪性需留意（约定事件命名 + 中文日志）；避免过度事件化——只在**真有跨域协作**时用事件，域内仍直接调用。
- 约束（写入 architecture-invariants）：域间不得 import 兄弟域；全图禁循环依赖；EventBus 投递若跨线程须线程安全，订阅者触碰游戏状态前经 `SchedulerPort` **按归属**切到正确线程（Folia 无主线程，见 [ADR-0013](0013-threading-and-scheduling.md) 与 testing-and-quality §2）。

## 备选方案
- **域间直接调用**：紧耦合、易循环依赖——否决。
- **复用平台事件系统作域间总线**：平台相关、不可跨端、不可单测——否决。
- **引入重型事件总线 / 消息中间件**：违背简单优先，自有轻量 EventBus 足够——否决。
