# 验证门与质量底线（防质量漂移）

> 项目特定的测试与质量要求。通用反模式禁令（上帝类、长方法、复制粘贴、魔法值、吞异常、资源泄露、循环依赖、静态可变单例等）仍然适用。

## 1. 验证门（权威判据）
- **每个变更必须过验证门才算完成**，判据以**入库真源**为准：① `docs/PRD.md` 验收标准对应项满足；② 本文 §2 高风险区相关测试通过；③ 受影响组件全部测试绿（各模块按其 Gradle 测试 / 构建任务执行）。
- **完成以证据为准、不轻信报告**：声称"做完 / 修好 / 通过"前，必须出示上述各项的客观证据（命令 + 关键输出、失败用例从红转绿、有实机 / 集成 / 真实环境维度的附该维度复验结果）。拿不齐 = 未完成、继续做——不轻信任何"完成了"的口头报告（含子代理的汇报）。
- **被推翻就回流继续修**：声称完成后被实测 / 实机 / 用户验收推翻，即视为该变更未完成，**回到本任务对应技能的验证步骤继续修**，不另开新流程、不重标状态。
- **提交受验证门门控**：验证门未全绿不得 `git commit`（门控见 `git-commit.md` §3）。
- `.tmp/` 下实施计划的里程碑勾选**仅作开发期辅助**，不入库、不作权威判据（clone 后可能不存在）。
- **禁止**以注释、跳过、删除失败测试的方式让测试"通过"。
- 改功能代码前先跑相关测试确保通过；新增 / 改业务逻辑同步加测试。

### 1.1 测试分层（怎么分、在哪跑）
- **单元**：L0 纯玩法逻辑 / 协议编解码 / 领域状态机 —— 不连任何平台，最快最多，必须可穷举。
- **集成**：被测组件 + 假平台（test double）或单一真实平台模块，跑端口装配与特性注册等关键流程。**GameTest 仅 mod 加载器（Fabric/Forge/NeoForge）有；Bukkit 家族 / Sponge 用 MockBukkit / 测试设施 + 真实服手测**（FR-23）。
- **实机（E2E）/ GameTest**：mod 加载器用 **GameTest** 两套——**模拟服**（单人/集成 headless，`runGameTest`，in-process 回环自动跑）+ **realserver**（真实专用服，**服务端驱动、客户端验证**：等待程序化客户端进入 → 触发场景 → 客户端 + 服务端双重断言 → 客户端回报、服务端聚合单一权威报告，任一端失败即失败，镜像 AllinCore-New ADR-0020、见 ADR-0014），**均为 MVP 验收门**（见 PRD §6 / FR-23）；Bukkit 家族/Sponge（无 GameTest）在真实 Paper 等上脚本化 / 手测达同等覆盖。realserver 维度须用户实机确认。
- **何时跑**：单元 / 集成随每次改动；实机在发版前与每次平台 / 版本扩展时至少跑一遍并由用户确认。

## 2. 必测的高风险区
逐项穷举验证以下本项目最易错、错了代价最高的部分：

- **分层分离度（核心不变量）**：L0/L1 不得出现任何平台 / MC 版本原生 import；依赖方向单向；**全依赖图无环、功能域之间无互依**（跨域经 EventBus）。须有**自动化断言 / 构建期校验**穷举各核心模块，回归任何泄漏与环依赖。
- **平台发现与装配（SPI）**：ServiceLoader 发现并绑定唯一活跃平台；零平台、或**我方多入口同时激活**（融合服上既激活 Bukkit 又激活 Forge）时启动期失败快——融合服上多平台"存在"本身合法（见 ADR-0008）；`PlatformProvider` 装配后只读、不可变更业务状态；端口工厂构造的端口非空且行为符合契约。
- **版本适配装配（L4）**：MC 版本探测正确；选中匹配的 `vX_Y`；锚点版本边界（如恰好 1.20.1 与临近版本）装配无误；缺失版本实现时明确失败而非静默退化。
- **跨端协议（protocol）**：每个包的序列化 / 反序列化**往返一致**（byte-for-byte）；版本协商在 `CURRENT` 与 `MIN_SUPPORTED` 边界上正确（兼容放行、不兼容明确拒绝）；非法 / 截断字节不致崩溃。
- **端口跨平台行为一致性**：同一端口（如 SchedulerPort / MessagePort）在不同平台适配器下对同一输入行为一致——同一份 L0 测试应能跑过任一平台适配。
- **EventBus 与域间转发**：事件正确投递到所有订阅者（含跨域转发）；跨线程投递线程安全、订阅者碰游戏状态前经 SchedulerPort **按归属**切到正确线程（Folia 无主线程，见 ADR-0013）；异常订阅者不影响其他订阅者；无订阅者不报错。
- **线程 / 调度模型与线程安全**：涉及**服务端主线程**（命令 / 监听器 / tick）、**netty 网络线程**（包收发）、**客户端渲染线程**（HUD / 跨端消息渲染）；**Folia 无单一主线程**。命令 / 监听器触碰共享可变状态（封禁表 / 会话表等）必须线程安全；网络包接收在网络线程，触碰世界 / 领域状态前必须经 `SchedulerPort` **按归属**（runForEntity/runForLocation/runGlobal）切到正确线程、**而非笼统"主线程"**（依据 ADR-0013）；**客户端渲染只在渲染线程读不可变快照（volatile 引用交换）、不在渲染线程改共享状态**；不在主线程 / tick / 渲染线程做阻塞 IO 或远程调用；封禁成功后才踢人、踢人经 runForEntity 调度（Folia 下尤甚）；**涉及调度 / 线程的端口按平台写契约测试，不指望同一份 L0 测试通吃**。

> 每条都要写清要穷举的边界（竞态、非法迁移、往返一致、超时与降级、版本/平台边界），不能只测happy path。

## 3. 质量底线
通用反模式底线（任何项目都适用）：
- 分层依赖单向、不反向穿透（防上帝类 / 防泄漏底层细节到上层）。
- 平台 / 版本差异经 `FeatureGate` + 接口收敛，**禁止散落 if-else/switch** 堆砌可变逻辑。
- 锁 / 临界区职责单一、不嵌套，高开销 IO 一律在锁外。
- 核心计算尽量做成无副作用纯函数，便于穷举测试。
- 多处写操作必须在事务 / 原子边界内完成，**成功后**才触发对外副作用（发包 / 发事件 / 唤醒）。
- 中文分级日志（ERROR/WARN/INFO/DEBUG），不留 `System.out.println` 等临时调试输出。
- 不硬编码凭据 / 端口 / 超时 / 版本号等，走配置或常量（`VERSION` 是版本号唯一来源）。
- 平台原生对象不泄漏进 L0/L1；资源（连接 / 流 / 任务句柄）确保释放（try-with-resources 或等价机制）。
